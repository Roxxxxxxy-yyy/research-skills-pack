# 写作优化：直接、准确、自然

先把事情讲清楚，再让语言好读。作者面对读者展开论证，不与想象中的批评者反复协商。

这是 anti-defensive-writing 的本地增强版。保留上游署名和原版快照，见 [来源](references/provenance.md)。执行当前入口及按需参考，不叠加加载原版全文。

## 使用方式

- 起草时：从用户提供的材料形成主线，直接写成稿，在交付前执行表达检查。
- 润色时：默认进行适度的句段优化，保留原意和作者声音。局部请求只处理局部；“只改错字”“保留句式”等明确要求优先。
- 诊断时：用户只要求找问题，就指出原句、阅读障碍及修改方向。
- 明确要求重写时，才大幅调整结构。证据不足造成的论证缺口单列，不能靠润色填平。
- 中文沿用自然、专业的中文表达；英文遵循目标文体。沿用用户的语言、术语和期刊要求。

学术稿件读 [学术写作](references/academic.md)；报告、技术方案、书稿、演讲与英文表达读 [文体适配](references/genres.md) 的相关部分。遇到难判断的改写读 [边界与实例](references/examples.md)。简单改句无需加载全部参考。

## 先识别内容，再判断语气

编辑前辨认：写给谁、这段承担什么任务、作者的主要判断、支撑材料和请求的修改幅度。能从原稿推断的直接处理，关键信息缺失才询问。

对每处疑似防御表达，判断它提供了什么：

| 实际作用 | 处理 |
| --- | --- |
| 回应真实问题、界定概念、说明必要条件 | 保留内容，压缩冗余 |
| 限定证据或适用范围，删去会改变理解 | 保留或等义改写，放在相关主张旁 |
| 披露影响结论的方法缺陷或不利结果 | 清楚呈现，不能美化掉 |
| 预先道歉、假想反驳、空泛示弱、重复澄清 | 删除或改为直接陈述 |

实用判断：删掉后，事实、逻辑、操作和读者判断是否改变？会改变就保留有效信息；不会改变、只剩自保语气的可以删。

## 消除防御性写作

- 让观点、发现、行动或研究对象尽早出现。删除“有必要先强调”“为了避免误解”等没有实质内容的开场。
- 把无用的否定式界定改为具体研究范围或实际主张。概念辨析、真实反驳、禁止事项和排除条件需要否定时照常使用。
- 合并“或许可能在一定程度上”等叠加限定。保留与证据匹配的一个限定，或说明具体不确定性来源。
- 用实际工作和发现替换“仅仅做了初步尝试”“只能提供有限参考”等价值自评。“试点”“初步”若准确描述设计或阶段，应保留。
- 只有关系确实转折或让步时，才用“然而”“尽管”“虽然”。不要给顺接的信息强加冲突。
- 同一限制不必在每段重复；会影响某句主张解释的限定留在该句附近。不要为了清爽把关键条件全部移到文末。
- 正文不替作者预演整套审稿辩护。审稿回复直接回应已提出的问题，准确承认已证实的错误。

## 优化论证与组织

- 先找本段要让读者理解的一件事。把证据、解释和推论按实际关系接起来，移除偏题铺垫。
- 检查主张是否有支撑、理由是否真的推出结论。缺少证据时收窄主张或标记缺口，不补写想象中的机制。
- 优先让段落开头承载主要信息；叙事、悬念和文体需要铺垫时保留合适顺序，不强制每段都变成结论句。
- 用共同主题、明确指代和承接上一段的关键词连接段落。转折词不能替代逻辑；“因此”需要前文提供推导依据。
- 合并同义重复，保留必要的解释层次和例子。不要把有推理过程的文章压缩成结论清单。
- 收尾交代本段或全文实际得到的认识、行动或未决问题。没有新信息就收笔，省去例行升华和泛泛展望。

## 优化中文句子与声音

- 尽早交代主语与核心动作，拆开多重定语和连续抽象名词。“对……进行分析”通常可写成“分析……”。被动句有明确用途时保留。
- 让“其”“这一”“该机制”等指代有唯一、可识别的对象。术语一致优于反复换近义词；不能把不同构念合并成同一个词。
- “赋能”“多维协同”“系统性重塑”“深层逻辑”“具有重要意义”等需要具体内容支撑。材料有内容就写内容，没有就删除空话；不为替换套话编造事实。
- 减少连续的对称排比、整齐三段式、“不仅……更……”“不是……而是……”、冒号标题及破折号。按语义需要使用，不建立机械禁词表。
- 用长短适当的完整句展开思路。不要为追求简短把正文切成口号，也不要用生僻词、华丽修辞或刻意口语制造“人味”。
- 维持作者原有的专业程度、情绪、节奏和有辨识度的表达。正式稿不自动改成聊天，个人叙述不自动改成公文。
- 文体诊断依据阅读障碍和信息功能。词频与句式不能判定作者身份，不报告“AI概率”或承诺规避检测。

## 语义保真

修改时逐项核对以下不变量：

- 数字、符号、单位、时间、样本、条件、否定、比较对象、效应方向及大小。
- 相关与因果、假设与发现、实际与计划、模拟与真实、探索与验证的区别。
- 引用所支持的主张、术语定义、引语原文、公式、交叉引用和必要方法细节。
- 禁止事项、前置条件、例外、操作顺序、义务和承诺强度。

发现原文矛盾或缺失时，在修改说明中指出具体位置和待核实信息。可以保守改写，但不擅自替用户决定事实。没有实际核验的文献不声称已核验。

## 最后一遍检查

通读成稿而非逐词替换：是否先给了有用信息？是否仍在回答假想质疑？是否有重复、空泛评价、跳步推理或突兀转折？必要条件和不利信息是否完整？句子是否自然可读？

检出问题后修订对应位置，随后对照原稿检查语义。达到用户的文体与修改幅度要求即可交付，不为凑轮次反复改写。

## 交付

默认先给可直接使用的成稿。大幅调整时简述关键修改；存在事实待核实项时单列。用户要求对照或修改记录时再提供相应形式。

不默认附长篇诊断、打分、自评、“已全面优化”式保证或结尾邀约。保持必要的 AI 使用披露；正式稿按目标期刊或机构规范处理。

涉及文件时，沿用适合该文件格式的编辑与检查流程。本技能负责文字，不宣称完成未执行的排版、文献或统计检查。新建输出文件通常另存；明确授权的原位修改按要求执行。
